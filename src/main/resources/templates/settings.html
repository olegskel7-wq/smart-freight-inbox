Notifications

When enabled, a notification with the draft is sent to the operator's inbox after each AI processing. Disable if you prefer to check drafts directly in the UI.

Auto-send ON OFF

When the pipeline is confident enough in a draft, send it without operator review. Confidence is computed from verifiable facts (type classified, identifier found in the backend, rate matched) and is shown on every ticket — watch the scores for a while before switching this on.

0.0–1.0. A draft is auto-sent only when its confidence is at or above this value. Default 0.8 = identifier found in the backend AND a specific type assigned.

Chase silent quotes automatically. When a reply to an RFQ is sent, a one-shot follow-up is scheduled; if the customer has not been in touch after the delay below, a gentle "just following up on our quote" nudge is composed. Delivery reuses the auto-send gate above: RFQ is not auto-sent by default, so each nudge appears as a draft for review unless you allow-list RFQ for auto-send.

Hours of customer silence after the quote was sent before a single nudge is sent (e.g. 48). A reply from the customer cancels the nudge.
AI Prompts

Tune the prompts sent to the local LLM for each pipeline step. Changes take effect immediately — no restart needed. Use the placeholders below; they are filled in at request time:

  • {email} — the customer's email body
  • {itemContext} — looked-up item data (drafting prompt only)
  • {rateContext} — matched carrier rates with sell prices (drafting prompt only); without this placeholder matched rates are appended to the end of the prompt

How to change SMTP

Per-tenant outgoing SMTP is managed per mailbox above — no restart needed. The platform fallback account (used when a mailbox has no SMTP of its own) comes from the .env file in the project root: 

SMTP_HOST=smtp.gmail.com
SMTP_PORT=587
SMTP_USER=your@gmail.com
SMTP_PASSWORD=your-app-password
MAILBOX_ENCRYPTION_KEY=<openssl rand -base64 32>

Then restart: docker-compose up --build backend
